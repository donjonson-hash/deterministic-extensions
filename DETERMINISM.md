# Контракт детерминизма v1

## Определение

При одинаковых полных входных данных, настройках, версии алгоритма и поддерживаемой среде результат должен совпадать в заранее определённом представлении. Для отчёта это canonical JSON, для сохранения файла — байты UTF-8, для перехода состояния — состояние и статус команды.

Это не обещание одинаковых пикселей во всех браузерах, минимального diff, корректности пользовательского кода или одинакового порядка прихода событий. История является частью входа редуктора. Две истории с одинаковыми конечными документами дают одинаковый отчёт сравнения, но могут иметь разные ревизии и Undo.

## Разделение ответственности

1. **Документ:** исходный текст и BOM. CRLF, CR, LF и смешанные переносы сохраняются.
2. **Сравнение:** отдельное нормализованное представление. Нормализация для сравнения не переписывает документ.
3. **Сессия:** A/B, ревизии, история B и идентификаторы принятых команд.
4. **Адаптер:** файлы, DOM, worker, скачивание. Он передаёт явные входы ядру и применяет только актуальные результаты.

В ядре нет чтения часов, случайности, сети, локали, DOM или хранилища. `gates.mjs` — небольшой явно создаваемый адаптер с состоянием счётчика, а не чистая функция; его последовательность зависит только от вызовов.

## Команды и атомарность

Поток изменения: сформировать предложение из показанных данных → проверить схему, ID, ревизии и исходные документы → вычислить новое состояние → заменить текущее состояние один раз.

Нельзя молча пересоздавать устаревшую команду под новые данные, применять часть операции или подбирать приблизительное место вставки. Отклонённая команда сохраняет прежний объект состояния. Повторно принятый ID остаётся использованным после Undo. Redo — новая команда истории, а не повтор старого Use A.

Гарантия ID действует внутри одной сессии. Перезагрузка создаёт новую сессию; долговременная идемпотентность, журнал после сбоя и транзакции между вкладками в v0.1 не реализованы. Они потребуют отдельного формата хранения и транзакционного адаптера.

## Фоновая работа

Каждый независимый поток получает свой gate. Контекст включает все влияющие настройки и версии парсеров. Перед запуском выдаётся билет; перед показом ответа проверяются последний билет, текущая ревизия и контекст. Повторный ответ по принятому билету отклоняется. Gate не отменяет вычисление и не является механизмом авторизации.

Новый запрос чтения файла инвалидирует предыдущий. Изменение состояния во время чтения также делает результат устаревшим. Для новой сессии создаются новые gate и worker: сообщения прежней сессии нельзя подключать к новой.

## Ограничения и отказ

Объём ограничен фиксированными пределами документов и истории, описанными в API. При превышении — явный отказ. Алгоритм не выбирает результат по таймауту или скорости компьютера. Ограничение времени для остановки теста допустимо; менять из-за времени сам отчёт сравнения нельзя.

Шаблон сравнивает строки по индексу. Вставка в начале может отметить множество последующих строк; это ожидаемое ограничение `line-index-v1`. Полное Use A копирует исходный формат A. Это отличается от правил переноса отдельного блока в Code Compare Local.

Редактирование textarea создаёт новый документ на основе текста, который вернул браузер; переносы могут стать LF. Поэтому «точные исходные байты» относятся к неизменённым импортам и сохранённым снимкам истории, а не к отредактированному вручную файлу.

## Сборка и проверка

ZIP содержит отсортированные пути, фиксированные метаданные, неизменённые исходники и не использует сжатие. Упаковщик сравнивает результат при другом порядке обхода. SHA-256 обеспечивает проверку целостности, но не является цифровой подписью автора.

Тесты проверяют нарушения контракта: неверный UTF-8, разные окончания строк, stale/replay, Undo/Redo, сериализацию команд и перестановку фоновых ответов. Это воспроизводимые регрессии, не формальное доказательство для всех возможных входов. Статические регулярные выражения — дополнительные ограниченные проверки, не полноценный аудит безопасности.

## Правило расширения системы

Новая возможность сначала получает явные входы, версию политики, способ сравнить результат и сценарии отказа. Затем — реализацию и проверки. Изменение смысла входа, результата или операции требует версии контракта и описания миграции.

Синтаксический анализатор можно добавить как локальный worker с фиксированной версией грамматики. OCR, внешние API и LLM — отдельные адаптеры; повторяемость их ответов нельзя объявлять свойством ядра. Выполнять загруженный пользователем код для «проверки» шаблон не должен.
