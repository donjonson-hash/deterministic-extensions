# Deterministic Extensions

Версия **0.2.0** — самостоятельная основа для браузерных расширений, в которых результат должен быть воспроизводимым, изменения проверяемыми, а исходные данные сохраняться без потерь.

Система состоит из контракта разработки, модулей ядра, рабочего расширения-примера, генератора нового проекта и проверок. LLM, ключи API и платные сервисы для работы расширения не нужны. Пример работает локально, не запрашивает разрешений браузера и не отправляет файлы в сеть.

Это новый фундамент на основе опыта Code Compare Local и Compare These Texts. Существующие проекты **не переведены** на него автоматически. Сравнение в шаблоне — простой алгоритм по номерам строк; промышленный движок сравнения и проверка синтаксиса сюда не перенесены.

## Пилот для целого проекта

Новый локальный интерфейс принимает связанный набор изменений нескольких файлов, показывает версии до/после, запускает выбранные проверки в отдельной копии и создаёт одну Git-ветку с возможностью Undo/Redo. Исходные рабочие файлы сохраняются. Для демонстрации нужны только Node.js 24.15+ и Git:

```bash
node scripts/project-demo.mjs
```

Откройте ссылку из терминала и пройдите сценарий с тремя файлами. Подключение своего проекта, JSON-формат и ограничения описаны в [docs/PROJECT-PILOT.md](docs/PROJECT-PILOT.md). Это браузерная страница с локальным Node-компонентом; интеграция в расширения и AI-чаты — следующий этап.

## Быстрый запуск расширения-примера

Требования: Node.js 24.15+, Python 3.11+, npm. Для расширения — Chrome/Chromium 138 или новее.

```bash
npm ci --ignore-scripts
npm run verify
```

В Chrome откройте `chrome://extensions`, включите режим разработчика, выберите «Загрузить распакованное расширение» и укажите `dist/extension`. По кнопке расширения открывается рабочая область. При первой установке открывается инструкция.

Для сборки без установки инструментов тестирования достаточно:

```bash
python3 scripts/build.py
```

В `dist/` появятся структура расширения, ZIP расширения, отдельный `project-pilot-0.2.0.zip` для запуска проекта и `build-manifest.json` с SHA-256 каждого файла. На входе допускается UTF-8 с BOM или без него. Пределы: 1 MiB, 200 000 UTF-16 единиц, 4 000 строк. До 50 состояний B доступны для Undo; после 2 048 принятых команд нужна новая сессия.

## Что гарантирует контракт

| Область | Правило |
| --- | --- |
| Результат | Одинаковые документы, политика и версия алгоритма дают одинаковый отчёт |
| Файл | Неизменённый UTF-8 файл выгружается с исходными BOM, переносами и последним переводом строки |
| Изменение | Команда проверяется целиком до изменения состояния |
| Повтор | Принятая команда с тем же ID не применяется повторно, даже после Undo |
| Актуальность | Изменение исходных данных делает старую команду неприменимой |
| Undo/Redo | Восстанавливается полное состояние B, включая формат файла |
| Фоновые операции | Устаревший результат не заменяет результат для текущей ревизии и настроек |
| Упаковка | Одни и те же входные файлы дают одинаковые байты ZIP без времени сборки |

Полный контракт и ограничения: [DETERMINISM.md](DETERMINISM.md). API: [docs/CORE-API.md](docs/CORE-API.md). Поведение интерфейса: [docs/TEMPLATE.md](docs/TEMPLATE.md).

## Структура

```text
src/project/      локальный Git-адаптер и HTTP-сервер проекта
project-ui/       просмотр набора файлов, проверки, ветка и Undo/Redo
src/core/         документы, сравнение, команды, история, контроль результатов
template/         автономное MV3-расширение с A/B, Use A, Undo/Redo и Download B
tests/            проверки инвариантов ядра
scripts/          создание проекта, сборка, проверки, браузерный сценарий
docs/             API, внедрение и границы первой версии
.github/workflows/ci.yml  обязательные проверки в GitHub
```

## Новый проект из системы

```bash
python3 scripts/new-project.py ../my-local-extension --name my-local-extension
cd ../my-local-extension
npm ci --ignore-scripts
npm run verify
git init -b main
```

Генератор работает только с новой папкой, переносит исходники и проверки, не копирует Git-историю, зависимости и результаты сборки. Имя меняется в package/lockfile и манифесте; текст интерфейса остаётся примером для адаптации. Создание проекта само по себе не подтверждает его готовность к публикации в магазине.

## Проверка интерфейса

```bash
npx playwright install chromium
REQUIRE_EXTENSION=1 npm run test:browser
```

В CI требуется настоящее установленное расширение. Для ограниченной локальной среды допустим диагностический запуск с `CHROMIUM_EXECUTABLE=/path/to/chromium npm run test:browser`: если расширение не загрузилось, скрипт явно сообщает `local-page`. Такой результат проверяет интерфейс, но не заменяет проверку установки MV3. Текущий протокол: [docs/VALIDATION.md](docs/VALIDATION.md).

## Дальнейшее развитие

Сначала фиксируем контракт и проверяем шаблон. Затем внедряем отдельные адаптеры в существующие проекты без массовой замены кода. Порядок: [docs/ADOPTION.md](docs/ADOPTION.md).

Публичная лицензия пока не выбрана; `UNLICENSED` означает отсутствие предоставленной здесь лицензии для стороннего распространения. Внешние зависимости используются только для разработки и имеют собственные лицензии.
